# A red slice escalates to a human recovery gate after three denied test writes

ADR 0011's guard made "a test cannot be weakened to go green" airtight, and in the November E2E that airtightness became a trap: IMPLEMENTER wrote a test with a malformed import, `run_tests` stayed red, every test write — including the only repair — was refused, and the guard had no bound, so the model retried until the run's model-call limit ended it. A stronger model is not the fix; the contract needs an exit. So the guard gains one: after three consecutive denied test writes in the same red slice it raises an escalation the tool middleware does not answer, and the graph pauses at a dedicated **recovery gate**. While a slice is open — from its first permitted test write to the green `run_tests` verdict (or the refactor seam) that ends it — every write the guard lets through is journaled under `.k0-mem/snapshots/<run>/slice/`, each path's pre-slice bytes (or its absence) plus the digest of the agent's last write. The gate offers the human two answers. `recover` restores exactly the journaled paths — pre-slice bytes back, slice-created files removed — after checking every path's current bytes match an image the journal recorded, then retries IMPLEMENTER fresh with a green guard and a new journal. `stop` ends the run stuck with the working tree untouched. There is deliberately no keep or unlock answer: the guard cannot tell a broken test from a legitimate red one, and neither can the agent, so the failing test is never editable in place — the only sanctioned paths are roll the slice back or leave it.

## Considered Options

- Reuse `limit_hit` with a third reason and teach its retry to roll back: rejected, because `limit_hit`'s contract is "a pause, never a gate" and its retry's documented semantics are "files kept" — a recovery decision is a gate, and smuggling one into the pause hides the rollback behind a reason string.
- Snapshot the whole working tree at each green transition and restore that: rejected for granularity — it would clobber developer edits the slice never wrote, and the tracker path has no worktree snapshot to extend.
- A `keep`/`unlock` answer that grants a one-off test edit: rejected, because it re-opens the exact hole the guard closed — a human who believes the test is sound should say `stop` and fix it by hand, not bless an agent write.

## Consequences

- This supersedes the unbounded-denial implication of ADR 0011: its red/green/refactor contract, "writes to docs pass in either state" and the lock that makes a write one op all stand unchanged, but a red slice's test-write refusals now have a bound and an exit. The first and second denials still return to the model as ordinary guard errors.
- The journal's scope is the recovery contract's safety: it contains only paths IMPLEMENTER's own tools wrote in the current slice, so `recover` cannot touch earlier slices, pre-existing content or unrelated edits by construction. The slice opens at its first permitted test write — writes the guard allows before it (green-state docs writes, refactor edits) precede the slice and are never journaled, so recovery preserves even a path the slice itself later rewrote by restoring it to the pre-slice bytes recorded at the in-slice write. A slice that ends green clears the journal and rotates the slice id, so a leftover same-run manifest can never be mistaken for the new slice's.
- The journal also protects the live tree while the slice runs: a repeat write to a journaled path is refused when its bytes no longer match the recorded post-write image, so a developer edit between the slice's writes is never overwritten or carried as a stale pre-image.
- One conflicting path — current bytes matching neither the pre- nor the post-write image, a directory or link where a file or absence is expected, an ancestor swapped for a symlink, a corrupt or escaped backup — refuses the whole apply before anything mutates, and the gate re-asks naming the conflicts. A missing, malformed or another slice's journal refuses the same way; the slice id is checked before the `applied` marker so a foreign consumed journal can never fast-path.
- The apply is restart-safe and per-file atomic, never multi-file atomic: a durable `restore` marker moves `in_progress` to `applied`, only that durable intent lets a pre-image match count as progress, an applied journal is a no-op even if the tree later changes, and each path is rechecked as it is restored so a concurrent edit is never overwritten. A created file's restore removes only it and only the directories the slice itself created.
- The journal writes nothing but its own directory — the developer's `.k0-mem/.gitignore` is not the harness's to edit; excluding `snapshots/` at publication is #173's job.
- A `recover` retry is a fresh IMPLEMENTER attempt: new agent instance, green guard, empty journal, attempts reset, the rolled-back paths and the human's feedback in its brief.
- A crash between the escalation and the answer, or between the answer and the retry, replays safely: the pending gate is checkpointed, the journal is on disk, and re-running the gate re-reads both.
