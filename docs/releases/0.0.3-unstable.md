## Problem

0.0.2 reaches DONE on a scratch repo, but the release check (#24) showed `/full` is not reliable on a real one:

- `/full` depends on how SPEC writes `## Files`. Backticked or annotated bullets either skip TESTER→REVIEWER and print `done`, or stop at `stuck` (`FILE path is not a test path`).
- CODER writes one file per run: the first non-test path of `## Files`.
- `k0 scan` and every model call run silently (777 s with no output on `k0ntrol/`).
- The spec and test gates show a bare `›`; `k0 init .` writes `Project_topology/` without the repo folder; `cursor-agent` needs `--trust` outside the workspace; `/fast` drops the trailing newline.
- VALIDATOR is only the `test_cmd` exit code. The Q1 gates (complexity, coverage) were deferred to 0.0.3 (D28), and `AGENTS.md`'s cognitive complexity ≤ 6 rule is broken today by 8 functions because nothing enforces it.

## Solution

Make `/full` and `/fast` work on real repos: a strict `## Files` contract checked in code, multi-file CODER, a validator that proposes which files to redo, progress lines, and configurable validator gates. k0ntrol then proves it by building one of its own 0.0.3 features with `k0 /full` (self-hosting run, D19).

## Decisions (grilling 2026-10-09)

These go into design §10 as D39+ in the first sub-issue.

- **D39 · Scope:** stabilise `/full` on real repos + Q1 validator gates. Cross-repo and parent-folder `.k0-mem/`, other languages, ACP, AgentView, OTel/Langfuse and extra backends move to 0.0.4+.
- **D40 · Exit criteria:** E2E on a scratch repo, dogfood, and a self-hosting run: the progress-lines ticket (#48) is built with `k0 /full` on k0ntrol, the human only answers gates, the release notes record the % of that ticket's diff written by k0, and every stall opens a `[BUG]` against the harness instead of a manual edit.
- **D41 · #24 bugs:** fixed in one ticket at the start. `--trust` is passed to `cursor-agent` only when `.k0-mem/` exists at the root (`k0 init` is the consent).
- **D42 · Process:** same as 0.0.2. Spec `[MVP - 0.0.3]`, tickets `[FEATURE]` / `[CHORE]` / `[BUG]`, `/implement-spec` rounds, `docs/releases/0.0.3-unstable.md` holds a copy of this body. The board §8 moves to "0.0.3 ✓" in the release-check PR (`_render/merge_status.py`).
- **D43 · `## Files` contract:** SPEC writes `- <path> (create|change)`. The harness validates it right after SPEC: at least one test and one non-test path; `change` paths exist and `create` paths do not; all paths inside the repo and outside `.k0-mem/`; backticks around a path are tolerated. Invalid → the error is appended to `spec.md` and SPEC runs again, up to `max_retries`, then `stuck` with the reason. The spec gate shows the parsed list. The silent `done` path disappears.
- **D44 · Multi-file CODER:** one `code_write` per non-test path, in `## Files` order, each a fresh one-shot call with its target whole (D24). Files already written in the run go in as references. `/fast` does the same with its non-test `@file` paths. One VALIDATOR run and one combined diff at the end.
- **D45 · What to redo on red:** when the suite or a gate is red, the validator mode proposes the paths to redo; the harness keeps only non-test targets from `## Files`; none left → redo all; the last attempt before `stuck` always redoes all. The final gate's `code` exit uses the same selector over `review.md`. Each selection is printed (`↻ coder: b.py`) and recorded in JSONL. Precedent: the retrieval gate (D34): the model proposes, the harness decides (D22 holds).
- **D46 · Progress:** one line when each model call starts and one when it ends (`→ tester (<model>)…`, `✓ tester 12.3s`), from the same choke point that writes the JSONL event; `scan N/M` during scans.
- **D47 · Validator gates (closes Q1):** `gates: [{name, cmd}]` in `config.yaml`. They run after a green `test_cmd`; a non-zero exit is red and follows D45. They also run in `/fast`. Default is empty; `k0 init` writes commented examples (complexity, coverage) and `k0 doctor` lists the active gates. `code_rules.md` stays prompt guidance.
- **D48 · k0ntrol eats its own gates:** `complexipy` (cognitive complexity ≤ 6) and `pytest-cov` (≥ 90 %) as dev-only dependencies, enforced in CI. The functions above 6 are refactored first. Runtime deps stay `pyyaml` and `rich`.
