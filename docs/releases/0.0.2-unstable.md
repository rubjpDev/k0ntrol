## Problem

In 0.0.1, `/full` stops after TESTER: SPEC writes `spec.md`, TESTER writes tests, and nothing implements them. `k0 init` creates `.k0-mem/` folders and `Mem.md`/`Rules.md` templates, but no code reads or writes them. Every model call starts from only what the human passes with `@file`.

## Solution

`/full` runs the whole loop from design §6.1: SPEC → TESTER → CODER → VALIDATOR → REVIEWER → human gate → DONE. k0ntrol builds code memory with a scanner, keeps session memory through `reflect`, and the harness injects relevant memory into each agent's prompt through a retrieval gate.

## Decisions (grilling 2026-10-06)

These go into design §10 as D26+ in the first sub-issue.

- **/full:** SPEC → TESTER → CODER → VALIDATOR → REVIEWER → human gate with three exits: ok → DONE; spec wrong → SPEC with the review appended to `spec.md`; code wrong → review appended to `spec.md`, fresh CODER, then VALIDATOR and REVIEWER again. No automatic loop limit; the human decides at each gate. `/fast` is unchanged.
- **REVIEWER:** new mode, high model (like SPEC), writes `review.md`.
- **VALIDATOR:** still the `test_cmd` exit code. Q1 gates (complexity, coverage, `code_rules.md`) move to 0.0.3.
- **Memory scope:** scanner, `Project_topology/`, `General_mem/`, session memory, `reflect`, retrieval gate, FTS index. Cross-repo and parent-folder `.k0-mem/` (D1, D3) move to 0.0.3; `.k0-mem/` stays at the repo root.
- **Scanner:** Python through stdlib `ast` gives File, Function and Class nodes with `defines`, `imports` and `calls` edges. `calls` resolve by name inside the repo; unresolved calls are dropped. Every other git-tracked text file gets a File node only. Node ids use the qualified form from D3 (`<repo>:file:<path>`, `<repo>:fn:<module.qualname>`, `<repo>:class:<module.qualname>`) so cross-repo stays cheap later.
- **Node `desc`:** written by `bulk_reader` on the low model, files batched per call up to `threshold_lines`, cached by file hash. If a scan needs more than `scan_confirm_over` (default 50) calls, ask `y/n` first.
- **When the scanner runs:** `k0 scan`, plus a hash-based incremental rescan of changed files before `/ask`, `/fast` and `/full`. Decided in code (D22).
- **`Project_topology/<repo>/`:** human-owned. `init` writes templates (architecture, `strategy.md`, `code_rules.md`); agents only read.
- **Retrieval:** the harness queries FTS for candidates, the retrieval gate (low model) decides whether to retrieve and picks the top `retrieval_top_k` (default 5), the harness injects them. SPEC, TESTER, CODER, REVIEWER and `/ask` get memory; VALIDATOR does not. `General_mem/Rules.md` always goes in whole, outside the gate.
- **Session memory:** facts and episodes in SQLite, gitignored. The FTS index is derived and gitignored too.
- **`reflect`:** runs on DONE, every `reflect_every` (default 10) session turns, and on `/quit` to flush; in a daemon thread inside the session process. Writes facts and episodes freely; proposes `Mem.md` additions that the human approves `y/n`; never touches `Rules.md`.
- **Process:** work lives in GitHub issues on this repo (mattpocock skills). `docs/releases/0.0.2-unstable.md` holds a copy of this definition. Decisions keep going to design §10; ADRs are reserved for later.

## New config keys

`agents.reviewer.model`, `scan_confirm_over: 50`, `retrieval_top_k: 5`, `reflect_every: 10`.

## Testing

Same as 0.0.1: pytest never calls `cursor-agent`; tests pass fake `invoke`/`bulk_read` callables, like `tests/test_fast.py`. A slice is done when `uv run pytest -q` passes in full in `k0ntrol/`.

## Out of scope (0.0.3+)

Q1 validator gates, cross-repo and multi-repo `.k0-mem/`, extractors for languages other than Python, ACP server, AgentView/OTel, backends other than Cursor.

### Dogfood

Throwaway copy of `k0ntrol/`, own git repo, `k0 init .`, `k0 scan`, memory on. `test_cmd` pointed at that copy's pytest. Scan: 21 `bulk_reader` calls, exit 0, 777s.

Session: `/ask` where the harness chooses `bulk_read` (46s, answered from memory, no `@file`). `/fast` add a module docstring to `delegate.py` plus a test (112s, suite green, `y`, `done`). `/full` add a one-sentence docstring test for `should_delegate` (spec in ~45s, then `stuck`). Reflect wrote three facts and two episodes and proposed no `Mem.md` bullet.

Top 5 frictions, most painful first:

1. `/full` approved the spec and stopped at `stuck` with `FILE path is not a test path: tests/test_delegate.py`, because the `## Files` bullet was the whole phrase `` `tests/test_delegate.py`: change. ... `` and the tester's real `FILE` line did not match it, so coder, validator, and reviewer never ran.
2. `k0 scan` on this package took 777s (21 model calls) and printed nothing until it exited.
3. The spec gate and the test gate are a bare `›`, with `y/n` left unsaid, while only the final review prints `ok / spec / code`.
4. `/fast` dropped the trailing newline on `delegate.py` and `test_delegate.py`, so the diff shows `return line_count > threshold_lines` as a changed line even though the text is the same.
5. `/ask`, `/fast`, and `/full` give no step status while a model call or the suite is running.

### Release notes

`0.0.2-unstable` is the release name. The git tag for this release is `v0.0.2-unstable`. That tag maps to package version `0.0.2.dev0` (`k0ntrol/pyproject.toml` and `k0ntrol/src/k0ntrol/__init__.py`). `0.0.2-unstable` is not valid PEP 440; `0.0.2.dev0` is the form pip accepts. `k0 --version` prints `k0 0.0.2.dev0`.

What this release adds, against 0.0.1: `/full` continues SPEC → TESTER → CODER → VALIDATOR → REVIEWER → human gate → DONE. `k0 scan` writes Python file, function, and class memory. The harness injects retrieval-gated memory into `/ask`, SPEC, TESTER, CODER, and REVIEWER. `reflect` stores facts and episodes and can propose `Mem.md` bullets for `y/n` at the next prompt.

The human merges to `main`, creates the `v0.0.2-unstable` tag, and pushes the public repo. This check does not do those steps.
